# VibeLang Compiler Backlog

Scoped follow-ups parked during active work. Newest at top; finished items move to `git log`.

- types: immutability-by-default has three measured escape hatches, all documented in `docs/spec/mutability_model.md` §"Known Escape Hatches" and none of them diagnosed. (1) ALIASING IS NOT TRACKED: `a := Box { v: 1 }` + `mut b := a` + `b.v = 99` mutates `a` with zero diagnostics, and `xs := [1,2]` + `mut ys := xs` + `ys.append(3)` grows `xs` — `:=` copies the reference, not the value. (2) A receiver with no binding root (`f().append(v)`) has nothing to attribute the write to and is skipped; reads through `.get(...)` *are* followed to their root, free-function results are not. (3) Passing an immutably-held container to a `mut` parameter lets the callee mutate it, and there is no call-site form to record that. (1) is the load-bearing one and needs real reference/ownership tracking — a design shared with `docs/spec/ownership_sendability.md`, not a patch to `mutability.rs`.
- types: `const` is documented in the book (`appendix_a_keywords.md`, `ch03` §"Constants with `const`") and in `docs/spec/mutability_model.md`, but no part of it exists: `const` is not a lexer keyword, `const X: Int = 1` does not parse, and the "reassigning a const is a compile-time error" half of the mutability model is unimplemented. Immutability-by-default (`mut`, `E2110`, `E2111`, `E2112`) shipped without it; the spec now marks every `const` clause TARGET. Either implement module-level `const` with compile-time-evaluable initializers or delete the claim from the book.
- types: type-annotated local bindings (`x: T := expr`, `mut result: List<Int> := []`) are used in `book/src/ch10_modules_and_packages.md` (4 sites) but the grammar only accepts inferred locals — `try_parse_binding` requires `ident :=`. Either add the annotated form or rewrite those snippets.
- types: per-field mutability (`type Account { mut balance: Int }`) is deliberately NOT modelled — `E2111`/`E2112` key on the receiver binding instead. If a future design wants field-level permission, it needs a `TypeField.is_mut` bit plus a decision about how it composes with the receiver rule; the spec records the current answer as "the receiver binding decides".
- docs: `tooling/docs/validate_snippets.py` is red and its committed report is stale (`reports/docs/snippet_validation.json` says `checked_snippets: 1`; the book actually holds 473 `vibe`/`yb` fences, of which 49 compile). Two CI workflows call it (`docs-quality.yml`, `v1-release-gates.yml`). Needs either a fence convention for deliberately-failing snippets (ch03's immutability error demo is *meant* not to compile) or a book-wide snippet repair pass.
- types: `go`-boundary sendability enforcement is DESIGNED AND ATTEMPTED but NOT SHIPPED (attempt preserved outside the repo). Two adversarially-confirmed reasons it was held back: (1) it is not sound as scoped — a spawner taking a fn-typed parameter (`my_spawn(task: fn() -> Int) { go task() }`) called with two closures that write the same Map passes with zero diagnostics and still crashes 10/10, and channel laundering stays open, so the rule would advertise more safety than it delivers; (2) `collect_mutating_params` re-walks every function body per fixpoint round, so `vibe check` wall time grew 2.7x at call-depth 125, 6.1x at 250 and 7.9x at 500 — a compile-time regression invisible on today's small corpus. Ship only with an honestly-scoped claim (direct sharing only) plus a non-quadratic fixpoint.

- types: opaque nominal handle types for str_builder/net/ws (P0-13 layer 2, parked): the Json/JsonBuilder pattern is a hardcoded variant across `vibe_types::TypeKind` + `vibe_mir::MirType` + codegen mappings (new machinery per family), and net handles can't change type without breaking corpus code that annotates them as Int (e.g. `66_websocket_echo.yb` `ws_handle(conn: Int)`). Runtime live-handle registry shipped instead; revisit if a general opaque-handle TypeKind lands. Note: user code can bind `@native(...)` directly, which bypasses any nominal typing — consider restricting @native to stdlib modules.
- mir: the inliner substitutes raw argument expressions into the callee body, so a side-effecting argument is evaluated the wrong number of times, including zero. `x := maybe(false, bump())` where `maybe` only uses the parameter in an untaken branch prints `bump` then `0` in dev and just `0` in release (verified 2026-08-15). Fix needs argument pre-binding to temps before substitution.
- mir: `?` in a call argument position to an inlinable callee fails the release build. `t := twice(parse_it(s)?)` reports "codegen failed: unknown local t in function run" (verified 2026-08-15); the callee itself is `?`-free, so the tail-position and `?` candidate filters do not cover this shape.
- mir: `substitute_stmts` gives `Select` and `Match` statements no parameter substitution, so inlining a callee that matches on a parameter fails the release build with "unknown local c in function main" (verified 2026-08-15). Either substitute into both, or exclude such callees.
- codegen: assignment inside a `match` arm is silently a no-op. `match c { case Color.Blue => out = "blue" ... }` leaves `out` at its initial value in dev while arm dispatch itself works (verified 2026-08-15 with no inlining involved); either lower the assignment or reject it with a diagnostic.
- types: `convert.to_str` of a user-function call returning Str prints a pointer — HIR passthrough keys on the type hint while inference disagrees (reproduced 2026-08-13)
- types: closure literals bypass the return-conflict (E2201) and unknown-type (E2005) checks; call-site E2265 only partially compensates
- types: if/else as tail expression infers Void, causing a spurious E2201 on functions with a declared return type
- types: `@require` diagnostics are emitted twice (contract expression walked by both validation and lowering)
- diagnostics: E2005 spans anchor on the declaration rather than the offending type annotation — TypeRef nodes carry no span
- diagnostics: monomorphized return-conflict messages leak mangled instance names (e.g. `pick__Int`)
- codegen: float-to-string paths fail with spanless Cranelift verifier errors (interpolation, println, and the unused `to_str_f64` route)
- tooling: 13 example `.yb` files are absent from `examples_manifest.json` and escape the suite (how the Str-interpolation regression stayed invisible); add a full-corpus build sweep to CI
